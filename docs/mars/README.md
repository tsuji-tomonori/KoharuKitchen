# オートパイロットは黙らない — 全体企画

## An Autopilot Never Goes Silent — A Software Engineering Story to Mars

2026-09-27。「こはるキッチン」から舞台を大きく変える新企画の第一稿。この文書は企画の骨組み、[話の大筋](outline.md)は全4部の流れ、[キャラクター構成](characters.md)は人物と関係性の設計です。三つを一組で読んでください。

> 「少年。火星まで、あと何行だ？」

## 一行で言うと

**自動操縦を書く二十三歳のエンジニア・朝倉航が、有人火星船「かささぎ」の乗組員に選ばれ、自分のコードに仲間の命を預けて火星へ行き、帰ってくるまでの約四年の物語。**

## 企画の核

### 1. 「困った時に黙る機械」を、黙らない機械へ

航は十六歳のとき、島のみかん畑のために自動散布ドローンを作った。潮風でGPSを失ったドローンは、何の知らせもなく飛び続けて海へ落ちた。けが人はいなかった。持ち主の源田は、七十を過ぎて急斜面の手作業に戻り、こう言った。

> 「機械は、困った時に黙る。だから儂は、自分の手でやる」

航の作る物は、老人の仕事を楽にするどころか重くした。この一言が物語全体の問いになる。

- 自動操縦は、人間の代わりか。人間の仲間か。
- 機械が困ったとき、何を人に伝え、いつ手を返すべきか。
- 自分が書いたコードを、自分がいない場所で動かせるか。

航の最初の答えは「人間のミスをゼロにするため、全部を機械に任せる」。最後の答えは「間違えても黙らず、人を呼び、手を返す機械を、仲間と一緒に作る」。

### 2. 自分がいなくても、船が帰ってこられる仕組み

「こはるキッチン」の到達点は「自分がいなくても、店と仲間が約束を守り続けられる仕組み」でした。この企画でも同じ到達点を、より切実な形で置きます。

- 地球との通信は片道で最大二十分ほど遅れる。地上の天才に聞いても、答えが来る前に事態は進む。
- 着陸船が火星へ降りるとき、航は周回軌道に残る。自分の書いたコードが、自分の乗っていない船で、仲間を降ろす。
- 帰路では、航しか読めないコードを「欠陥」と呼び、仲間へ手渡す。

### 3. 選ばれた者と、選ばれなかった者が同じ船を飛ばす

選抜で落ちた二人は、地上側の主役になる。

- 自動操縦の候補で最高得点だった東雲透は、地上の飛行ソフトウェア責任者として、異なる頭で書いた「予備の自動操縦」を船に載せる。
- パイロット候補の久我隼人は、地球から船へ呼びかける声（交信担当）になる。

火星の上空で航のコードが止まったとき、船を救うのは東雲が書いた予備の自動操縦と、二十分前に地球を出た彼の手紙です。「選ばれなかった」を美談で包まず、悔しさを抱えたまま仕事で並ぶ関係を描きます。

## SWEBOKとの関係

「こはるキッチン」と同じく、IEEE Computer Society の **SWEBOK Guide V4.0a** を主要な知識体系として使います。

- 物語の章立てはSWEBOKの章立てに合わせない。時間軸は「選抜→訓練→航行・火星→帰還」。
- 本文ではできる限り用語を説明しない。人物が困り、試し、失敗し、選ぶ場面を先に描く。
- 各話の後に、既存企画と同じ五つの補足を置く。
  - この話で起きていたこと
  - ソフトウェアエンジニアリングでは何と呼ぶか
  - なぜ有効なのか
  - どんな場合には使えないか
  - SWEBOKではどこで扱われているか
- 物語上の判断や宇宙船の仕様を、SWEBOKに書かれた内容であるかのように扱わない。対応するKnowledge Area（KA）と、原文に含まれない創作部分を分けて管理する。

## 作品の方針

### 悪役を作らない

「こはるキッチン」の方針を引き継ぎます。計画責任者は予算と発射の窓を守り、首席パイロットは技術者に責任を押し付けられた過去から機械を疑い、東雲は選ばれなかった悔しさを隠さない。誰もが「なぜそう考えたか」が分かる人物にします。

### 知識を言い当てて勝たせない

航が正しい用語を言ったから解決する話にしません。仮説を立て、試し、仲間の手を借りて、現実の状況が変わるところまで描きます。航の強みで解けない問題（手で降りる感覚、音で分かる故障、人の脈）は仲間が解きます。

### 宇宙の描写は「本当らしく、断定しない」

- 実在の宇宙機関・企業・計画名は使わない。機関は架空の「国際深宇宙機構（IDSA）」、船は「かささぎ」と「つばめ」。
- 軌道・通信遅延・放射線・着陸などは実際の知見を下敷きにする。ただし数値は物語に必要な範囲で丸め、実在計画の仕様として示さない。
- 技術監修を通していない内容は、補足で「創作上の設定」と明記する。

### 恋愛で関係を代替しない

船長と航は、師と弟子であり、指揮官と部下であり、最後は互いの脈を確かめ合う仲間。恋愛の含みで関係の緊張を作らない。全員成人。

### 傷を死別でそろえない

人物の過去は、本人が選び損ねた日常の出来事から作ります。航の墜落したドローン、船長の「全部緑」、首席パイロットの「操縦ミス」と書かれた報告、整備士の隠した腰。誰も死なせずに重さを出します。

### 自動操縦の構成（物語上の仕掛け）

- **主系**：航が中心になって書く自動操縦。状態を常に言葉と表示で乗員へ伝え、自信を失うと人を呼び、手を返す。
- **予備系**：東雲の地上チームが、同じ仕様書から別の考え方で書いた自動操縦。主系と同じ誤りを持たないことが目的。
- **計算機**：三台の多数決。放射線で一台が狂っても、残りが正しい答えを出す。四台目は質量の都合で削られた。
- **削られた機能**：着陸直前に危険な岩を見つけて降りる場所を選び直す機能。発射の締切に間に合わず、飛行中に完成・検証して載せる。

## ゴール

読み終えた読者が、次のことを登場人物の経験として思い出せる状態を目指します。

- 機械に任せることと、人から手を奪うことは違う
- 「全部緑」は、何も知らせないことと区別がつかない場合がある
- 自分の仮定を、仕様書の一行として残す
- 失敗の原因を人ではなく仕組みの中に探す
- 自分しか分からないものは、完成ではない
- 選ばれなかった場所にも、仕事と誇りがある

そして必要になったとき、「そういえば、かささぎで似たことが起きていた」ところから、正式な用語・標準・書籍へ進める作品にします。
